# Обновление: обвязка и курсы

Две вещи в этом рабочем пространстве меняются отдельно друг от друга:

| Что | Чем обновляется | Что обновление **никогда** не трогает |
|---|---|---|
| **Обвязка botai** — политика (`AGENTS.md`), скиллы, агенты, команды, скрипты, документация | `make update` | `courses/`, `progress/`, `.botai/`, `dist/` — всё, что принадлежит обучающемуся |
| **Курс** — репозиторий курса в `courses/<slug>/` | `make course-update COURSE=<slug>` | ваши правки, заметки и ответы внутри курса |

Это разделение намеренное: обновление обвязки не может переписать материал
курса, а обновление курса не может переписать политику.

Главное правило одно:

> **Обновление не имеет права потерять работу.** Если оно не может пройти
> безопасно — оно останавливается и говорит почему. Оно никогда не удаляет
> каталог и не клонирует его заново, и никогда не подставляет другой источник.

## Обновление обвязки

```bash
make update-check     # есть ли новая версия? код возврата 10 = есть
make update-dry-run   # что изменится — ничего не записывает
make update           # выполнить
```

То же самое без `make` (любая ОС, включая Windows):

```bat
py -3 scripts\cli.py update --check
py -3 scripts\cli.py update --dry-run
py -3 scripts\cli.py update
```

### Как читать отчёт

| Строка отчёта | Что означает |
|---|---|
| `добавлено` | новых файлов столько-то (новый скилл, новый документ) |
| `обновлено` | версия обвязки заменила файл; локальных правок в нём не было |
| `сохранены локальные версии` | **самая важная строка.** Эти файлы отличаются от установленных, поэтому оставлены как есть |
| `устарело, оставлено` | таких файлов больше нет в обвязке; они сохранены |
| `без изменений` | файл совпадает с версией обвязки |

Файл, который вы правили сами, **не перезаписывается**: обновление сравнивает
его хэш с хэшем, записанным при установке (`.botai/install.json`). Если хэши
разошлись — это ваша правка, и она сохраняется.

Заменить такие файлы версией обвязки всё же можно:

```bash
python scripts/cli.py update --overwrite
```

Перед заменой старые версии копируются в `.botai/backup/<метка времени>/`.
Это страховка, а не разрешение не думать: посмотрите список заменённого.

Удалить файлы, которых больше нет в обвязке:

```bash
python scripts/cli.py update --prune
```

Тоже с копией в `.botai/backup/`.

### Что помнит установка (и почему это важно)

`make install` пишет `.botai/install.json`: версию, источник, ветку, время и
**хэш каждого файла обвязки**. Это база сравнения, и на ней держится вся
защита работы:

- файл, чей хэш совпадает с записью, — версия обвязки, её можно заменить;
- файл, чей хэш отличается, — **ваша правка**, её обновление сохраняет;
- файл, которого в записи нет вовсе, тоже считается вашим (ошибаемся в
  безопасную сторону: лучше лишний раз сохранить, чем один раз затереть).

Запись имеет версию формата (`schema`). Когда формат меняется, обновление
поднимает схему перед сверкой файлов. Важная деталь: при этом хэши **не**
перезаписываются текущими локальными — иначе все правки разом объявились бы
«нетронутыми» и были бы затёрты. Отсутствие пути в записи означает «сохранить»,
а не «перезаписать».

Удалять `.botai/install.json` не нужно и не рекомендуется: без него первое
обновление будет осторожным (все несовпадающие файлы сохранятся), но оно
потеряет способность отличить вашу правку от устаревшей версии обвязки.

### После обновления

Если обновление затронуло `AGENTS.md`, `opencode.json`, `.opencode/` или
скилл, который уже загружен в текущей сессии, — **перезапустите агента**.
Конфигурация и политика читаются один раз при запуске, и продолжать работу по
старому тексту означает тихий рассинхрон версий.

### Откат

Обновление обвязки — это обычная замена файлов, поэтому откат — это копирование
их обратно:

```bash
# посмотреть, что было заменено в последнем обновлении
ls -R .botai/backup/

# вернуть один файл
cp .botai/backup/<метка>/AGENTS.md AGENTS.md
```

Если проект — git-чекаут обвязки (`git clone` самого botai), обновление идёт
через `git fetch` + `git merge --ff-only`, и откат — обычный `git`:

```bash
git -C . log --oneline -5      # что пришло
git -C . revert <коммит>       # откатить конкретное изменение
```

## Получение и обновление курса

Курс — это отдельный репозиторий, который лежит в `courses/<slug>/`.

```bash
make course-add COURSE_URL=https://github.com/<владелец>/<курс>.git
make course-set COURSE=<slug>
make course-update-check COURSE=<slug>   # код 10 = есть обновление
make course-update COURSE=<slug>
make detect-courses                      # источник, версия, незакоммиченные правки
```

### Предпросмотр и повторное получение

`course-add` поддерживает `--dry-run` (в `make`-форме: `python3 scripts/cli.py
course-add ... --dry-run`): команда печатает точный план — адрес, ссылку и
каталог назначения — и **ничего не пишет**, включая сам каталог курса. Это
проверяется тестами, а не только описано.

Каталог, который уже существует и не пуст, не перезаписывается. Если нужно
получить курс заново, есть два безопасных пути:

```bash
# обновить существующий курс из его собственного источника
python3 scripts/cli.py course-update --course <slug>

# или получить рядом вторую копию под другим именем
python3 scripts/cli.py course-add --url <git-url> --name <slug>-2
```

Разрушительного «переустановить с нуля» больше нет: в каталоге курса может
лежать работа за семестр, и удалять её ради повторного клонирования
недопустимо. Прежний флаг `--force` теперь завершается отказом с этими двумя
подсказками.

Имя курса — это **имя, а не путь**. Отвергаются разделители (`a/b`), `..`,
абсолютные пути, буквы диска, NUL, зарезервированные имена Windows и имена с
точкой или пробелом на конце. Существующие каталоги с «легаси»-именами
(например, с кириллицей) продолжают работать. Каталог внутри `courses/`,
являющийся симлинком или junction за пределы рабочего пространства,
отвергается, а не используется.

### Что означает запись `.botai-course.json`

При получении курса рядом с ним (внутри `courses/<slug>/`) создаётся файл
`.botai-course.json`: источник, ветка, коммит, время получения и отпечатки
файлов. Он нужен, чтобы обновление знало, **откуда** курс пришёл и **что**
считается вашей правкой. Файл служебный; в отчётах о «грязном» дереве он не
учитывается.

### Что произойдёт в трёх неудобных случаях

**1. У вас есть незакоммиченная работа.**

Обновление останавливается и показывает список файлов. Два честных пути:

```bash
git -C courses/<slug> stash push -u -m 'перед обновлением'   # отложить
make course-update-commit COURSE=<slug>                      # закоммитить и обновить
```

`course-update-commit` **никогда ничего не удаляет**: он коммитит вашу работу и
только потом обновляет курс. Коммит делается **вашей** git identity: если
`user.name`/`user.email` не настроены, команда останавливается и просит их
настроить. Инструмент не подставляет фиктивного автора — коммит должен быть
вашим.

**2. В курсе есть ваши собственные коммиты.**

Быстрое обновление (`--ff-only`) невозможно, и обновление останавливается,
показывая, как перенести свои коммиты в отдельную ветку:

```bash
git -C courses/<slug> branch my-work     # сохранить свои коммиты в ветке
git -C courses/<slug> rebase <коммит-курса>   # или перенести их поверх курса
```

Это переписывание истории — решение принимает обучающийся, а не инструмент.
Поэтому команда только печатается, но не выполняется. `git reset --hard` в
подсказках **не предлагается**: он уничтожает незакоммиченную работу, а
обновление не имеет права её терять.

**3. Источник курса изменился.**

Если записанный источник и `origin` чекаута расходятся, обновление
останавливается и показывает оба адреса. Подмена источника — тоже решение
обучающегося: молча следовать за новым URL инструмент не будет.

### Чего обновление курса не делает

- не переклонирует курс «с нуля» — это как раз то, что уничтожает работу;
- не подставляет другую ссылку, если источник не отвечает;
- не выполняет `git reset --hard` и не коммитит от вымышленного автора;
- не трогает `progress/<slug>.md` — прогресс живёт в рабочем пространстве, а не
  в курсе.

### Импорт дневника прогресса (v1 → v2)

Дневник `progress/<slug>.md` в формате 1.x остаётся читаемым. Для переноса в
запись v2 (`.botai/state.sqlite3`) есть команда, которая сначала показывает
отчёт и пишет только по явному подтверждению:

```bash
make state-migrate COURSE=<slug>                  # отчёт, ничего не записано
make state-migrate COURSE=<slug> APPLY=1          # импорт
```

Что гарантируется:

- заявленное в v1 `mastered` импортируется как `practising` с сохранением
  исходного значения и основания: это было утверждение, а не доказательство;
- нераспознанные строки сохраняются с номерами для ручной проверки — догадки
  не подставляются;
- файл, описывающий нескольких обучающихся, отвергается без явного разделения
  (`--confirm-split stu-01=<id>`), потому что приписать одному человеку чужие
  строки хуже, чем спросить;
- исходный файл сохраняется целиком как артефакт и остаётся на месте.

## Обновление по расписанию

Обновление полезно, только если оно происходит. Ставьте его на расписание —
оно безопасно по построению: пишет только файлы обвязки.

**Linux / macOS (cron):**

```cron
0 9 * * 1 cd /путь/к/проекту && python3 scripts/cli.py update >> .botai/update.log 2>&1
```

**systemd (таймер):**

```ini
# ~/.config/systemd/user/botai-update.service
[Service]
Type=oneshot
WorkingDirectory=/путь/к/проекту
ExecStart=/usr/bin/python3 scripts/cli.py update

# ~/.config/systemd/user/botai-update.timer
[Timer]
OnCalendar=Mon 09:00
Persistent=true

[Install]
WantedBy=timers.target
```

```bash
systemctl --user enable --now botai-update.timer
```

**Windows (планировщик заданий):** задача раз в неделю с действием
`py -3 scripts\cli.py update` и рабочей папкой проекта.

Обновление **курсов** намеренно не ставится на расписание: в чекауте курса в
любой момент может лежать незакоммиченная работа, а планировщик не умеет
спрашивать. Его запускает человек или агент.

## Если что-то пошло не так

| Симптом | Что это значит | Что делать |
|---|---|---|
| `не удалось получить данные upstream` | нет сети, нет доступа к репозиторию или неверный адрес | это момент, а не факт: проверьте сеть и повторите; при повторной неудаче сообщите адрес и текст ошибки |
| `источник не похож на GitHub-репозиторий` | для файловой синхронизации нужен адрес GitHub; локальный каталог тоже поддерживается | используйте `--source <путь>` для локального источника или `--mode git` |
| `отказ: в проекте есть незакоммиченные изменения` | правки не закоммичены | `git stash` либо `git commit`, затем повторите |
| `отказ: история разошлась` | в курсе есть свои коммиты | перенесите их в ветку (команда печатается в отчёте) |
| обновление прошло, но агент работает по-старому | конфигурация читается при запуске | перезапустите сессию агента |
| обновление обвязки заменило нужный вам файл | он не был распознан как ваша правка | возьмите его из `.botai/backup/<метка>/`; в следующий раз правьте через запись в отпечатке: сохраните свою версию и запустите `make update` — она будет сохранена |

Обновление, которое упало, **не изменяет ничего**: архив скачивается и
распаковывается во временный каталог, и только потом файлы попадают в проект.
