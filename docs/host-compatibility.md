# Совместимость с хостами

Документ описывает, какие хосты ботай поддерживает, на чём основана поддержка
и — главное — **чего поддержка не означает**.

## Три состояния, и среднее важнее крайних

| Состояние | Что оно значит |
|---|---|
| `managed` | Конфигурация сгенерирована **и итоговый конфиг проверен**: разрешены только инструменты ботай и поставляемые навыки |
| `compatibility` | Политика и навыки применяются, ручной CLI доступен. Технических ограничений **не заявляется** |
| `HOST_UNVERIFIED` | Ограничения доказать нельзя: разрешён только compatibility или read-only учебный режим без операций |

`compatibility` — полноценный режим, а не урезанный. Именно он работает для
большинства хостов, и это нормально: обещать техническое ограничение там, где
его нет, было бы хуже, чем честно назвать границу.

## Почему `managed` выдаётся только по проверке

Соблазн, с которым борется `adapters.py`: объявить `managed` потому, что
конфиг *выглядит* правильным. Каждый из этих случаев делает профиль
декоративным, и каждый проверяется:

- **шаблон в разрешениях** (`botai_*` или `*`) — разрешит и те инструменты,
  которые появятся позже, включая административные;
- **`default: allow`** — запрет перестаёт что-либо значить;
- **неполный список запретов** — инструмент вроде `bash` или `webfetch`
  остаётся достижимым;
- **подагент с обходным инструментом** — `task` уводит модель в агента с
  более широкими правами;
- **включённое внешнее расширение** — плагин регистрирует собственные
  инструменты при старте;
- **отсутствие раздела разрешений** — это не «безопасно по умолчанию», это
  «неизвестно», а неизвестное не сертифицируется.

Проверяется **итоговый** конфиг, а не файл, который записал ботай: хост может
сливать глобальные настройки, подключать плагины и добавлять подагентов.

## Состояние на текущий репозиторий

```
python scripts/cli.py adapter-check --host opencode
```

**Текущий вердикт — `managed`.** Конфигурация исправлена (B17 закрыт):

- `permission` строится от `default: deny`;
- запрещены все обходные инструменты, которые OpenCode **действительно
  реализует**: `bash`, `edit`, `write`, `apply_patch`, `ast_grep_replace`,
  `webfetch`, `websearch`, `task`, а также все внешние MCP (`context7_*`,
  `github_*`, `engram_*`, `g4f-tools_*`, `gh_grep_*`, `roblox-studio_*`,
  `education-club_*`);
- явно разрешено только чтение и вопросы: `read`, `list`, `glob`, `grep`,
  `codesearch`, `lsp`, `question`, `skill`, `todowrite`;
- `education-club` выключен (`enabled: false`) до явной настройки:
  `EDUCATION_CLUB_CATALOG` не задан, и включённый каталог с несуществующим
  путём не работал бы всё равно.

### Почему важен именно словарь хоста

Первая версия проверки требовала запретов для `shell`, `execute`, `fetch`,
`multiedit`, `notebook_edit` — имён, которых в OpenCode **нет**. Такой конфиг
выглядит аккуратно и не защищает ничего: `read` и `apply_patch` остаются
доступны, а запрет `shell` не срабатывает, потому что такого инструмента не
существует. Поэтому список обходных инструментов задаётся **на хост**
(`HOST_BYPASS_TOOLS`), а не одним общим перечнем.

### Версия

Проверка сертифицирует **конкретный релиз**. Закреплено: OpenCode **1.18.26** —
на нём блок разрешений прочитан обратно через `opencode debug config`, который
печатает итоговую конфигурацию с учётом глобальных настроек и плагинов, и каждое
правило разрешилось так, как записано. Версия определяется автоматически
(`_detect_host_version`); при неизвестной или другой версии выдаётся
`HOST_UNVERIFIED`, и это не формальность: семантика разрешений между релизами
хоста меняется.

**Что это по-прежнему не значит.** Ограничены только инструменты ботай. Ваш
глобальный конфиг OpenCode содержит собственных агентов (среди них `free-agent`
с `bash: allow`) и пять плагинов; запрет `task` закрывает делегирование к ним
**из проектного профиля**, но запуск OpenCode с другим глобальным конфигом этих
ограничений не наследует. Для настоящей изоляции нужен отдельный профиль хоста
без посторонних агентов и плагинов.

## Что нужно для `managed`

```bash
python scripts/cli.py adapter-install --host opencode   # записать профиль в проект
python scripts/cli.py adapter-check   --host opencode   # версия определится сама
```

`adapter-install` пишет `botai-profile.json` **только в этот проект**.
Глобальные настройки не трогаются: инструмент, правящий пользовательский конфиг,
ломает все остальные проекты.

Профиль разрешает **конкретные имена** инструментов, не шаблон. Если позже в тот
же MCP-сервер добавят административный инструмент, он не окажется разрешён
задним числом.

## Хосты

| Хост | Состояние | Основание |
|---|---|---|
| OpenCode | `managed` на закреплённой **1.18.26** | правила проверены через `opencode debug config` |
| Claude Code, Cursor, Codex, pi, DSH | compatibility | адаптера нет; политика, навыки, ручной CLI |

Отсутствие записи в `TESTED_VERSIONS` — не «вероятно, работает», а «не
проверялось». Проверка без закреплённой версии даёт
`HOST_VERSION_UNTESTED` и не выдаёт `managed`.

## Что ботай обещает и чего не обещает

**Обещает** в `managed`:

- инструменты, ограниченные своей областью: курс, ученик, сессия;
- пути и URL не принимаются как аргументы ни одним инструментом;
- разрешение человека на операции нельзя выдать вызовом инструмента: такого
  инструмента нет.

**Не обещает**:

- **что это песочница.** Ограничены только инструменты ботай;
- **что на хосте с собственным bash модель не обойдёт их.** Именно поэтому
  `managed` требует проверенного конфига, а не доверия к тексту;
- **что текстовый спойлер невозможен.** Модель может выдать ответ прозой в
  обход всех проверок формы;
- **что модель вызовет `response_check` перед показом ответа.** На хосте без
  перехвата вывода это рекомендация, и адаптер обязан помечать
  `output_gate=advisory`.

`AGENTS.md` **не является файрволом**. Текстом ограничения не обеспечиваются;
он задаёт политику, а не границу.

## Каталог Education Club

```bash
python scripts/cli.py catalog-check --catalog "$EDUCATION_CLUB_CATALOG"
```

Каталог — вспомогательное средство **поиска** курсов. Добавление курса идёт
обычным путём с проверками путей и подтверждением; внешний `fetch_course` не
обходит их. Наличие инструкции о MCP не означает, что каталог входит в ботай.
