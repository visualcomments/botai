# Правила курса: что агенту разрешено

Документ описывает слой, который превращает обещание «оцениваемое задание не
получает готовый ответ» из абзаца инструкций в проверяемое правило.

## Зачем это нужно

`AGENTS.md` формулирует правило. Но правило, записанное только текстом,
модель применяет к себе сама — а значит, её можно переубедить: переписать
просьбу, назвать задание тренировочным, сослаться на роль или подсунуть
инструкцию внутри PDF. Поэтому решающая часть вынесена в код и считается из
**принятого контракта курса**.

Что это даёт и чего не даёт:

- **Даёт:** решение о помощи считается детерминированно, называет правило, на
  котором основано, и не меняется от того, кто последним записал файл.
- **Не даёт:** на хосте без перехвата вывода модель всё ещё может раскрыть
  ответ обычным текстом. JSON-проверка этого не закрывает, и документ не
  должен делать вид, что закрывает.

## Четыре команды

```bash
# 1. Посмотреть, что курс объявляет. Только чтение, ничего не исполняется.
python scripts/cli.py course-inspect --course <slug>

# 2. Принять контракт как политику. Это решение человека.
python scripts/cli.py course-accept --course <slug>

# 3. Что принято и что изменилось в рабочей копии.
python scripts/cli.py course-status --course <slug>

# 4. Разрешить ли конкретную помощь для конкретного задания.
python scripts/cli.py policy-check --course <slug> --assignment <id> --level SOLUTION
```

### `course-inspect`

Показывает: `course_id`, название, **права на материалы**, разрешён ли вклад,
оцениваемость каждого задания, число целей и модулей, и все найденные
дефекты. Ничего не пишет и не принимает. Курс без `botai/course.json` честно
называется курсом без условий.

Код возврата `3` означает «условия не объявлены» — принять нечего, выдумывать
оцениваемость нельзя.

### `course-accept`

Человеческая операция. В учебной поверхности MCP её нет: агент, способный
принять контракт, способен принять контракт, переклассифицирующий оцениваемое
задание в тренировочное.

Что происходит при принятии:

1. контракт и программа проверяются схемами;
2. программа проверяется на дефекты (см. ниже);
3. каждый объявленный файл задания должен существовать;
4. контракт и программа копируются в `.botai/accepted/<sha256>/`;
5. разрешённые материалы копируются в
   `.botai/materials/<course_id>/<revision>/`;
6. пишется `.botai/courses/<course_id>/binding.json`.

После этого правка `botai/course.json` в рабочей копии **не меняет политику**.
Иначе тот, кто коммитит последним, мог бы смягчить правила оценивания.

### `course-status`

Показывает принятые хеши, ревизию и расхождения с рабочей копией. Отдельно
выводит:

- изменение оцениваемости задания (`принято 'graded' -> в копии 'practice'`);
- новые задания, которых нет в принятом контракте (их оцениваемость —
  `unknown`, строгий режим);
- задания принятого контракта, исчезнувшие из копии.

Принятая политика при этом остаётся в силе. Чтобы принять новую ревизию,
нужен отдельный просмотр и отдельный `course-accept`.

### `policy-check`

Объясняет решение и правило:

```text
== политика помощи ==
  курс        : minimal-diff
  задание     : homework-3
  оцениваемость: unknown (not_declared)
  запрошено   : SOLUTION
  решение     : deny (SOLUTION_NOT_ALLOWED_FOR_ASSESSMENT)
  предел      : EXAMPLE
  правило     : policy.assessment_default_unknown
  готовый разбор этой задачи недопустим: оцениваемость «unknown»...
  вместо этого:
    - разобрать нетождественный тренировочный пример (EXAMPLE)
    - разобрать собственную попытку ученика без готового решения
```

Код возврата `0` — разрешено, `3` — отказано.

## Лестница помощи

Решение — самая строгая из границ. Оцениваемость сильнее стиля помощи, стиль
сильнее инициативы агента.

| Оцениваемость | HINT | EXAMPLE | SOLUTION |
|---|---|---|---|
| `graded` | да | да | **никогда** |
| `unknown` | да | да | **никогда** |
| `practice` | да | да | да |

Задание, которого нет в принятом контракте, — `unknown`. Значение по
умолчанию никогда не «вероятно, практика».

Стили помощи (`PREFERENCE_CEILING`):

- `hints` — предел `HINT`; просьба ученика его **не** поднимает, потому что
  стиль и есть заявление «не выдавай готовое». Поднимает только смена стиля.
- `hints-then-solution` и `solution-first` — предел `SOLUTION`.
- `prefer-ask` — выбор отложен ученику, поэтому явная просьба поднимает предел
  до оцениваемости, но не выше.

Предъявление проверки (`intent=check`) — **не помощь**. `assistance_level` не
назначается: иначе обычный вопрос портит историю помощи и может впоследствии
лишить ученика стадии `demonstrated`.

## Операции с внешним эффектом

`env_apply`, `course_prepare_apply`, `course_add`, `course_accept`,
`privacy_delete`, `privacy_export`, `teacher_import`, `update`,
`adapter_install` требуют разрешения человека, привязанного к **хешу
конкретного плана**. Разрешение одноразовое и истекает.

Модели недоступны в принципе: коммит, push, открытие PR, выставление оценки,
смена роли workspace, запись согласия, установка `mastery`, выдача разрешения.

Хост, который не умеет отличить человеческое разрешение от модельного,
операцию не выполняет. Режим «никогда не спрашивать» не является разрешением
на всё.

## Проверка программы курса

При принятии программа отклоняется, если:

| Код | Что найдено |
|---|---|
| `DUPLICATE_ID` | повтор идентификатора цели или модуля |
| `OBJECTIVE_MODULE_UNKNOWN` | цель ссылается на несуществующий модуль |
| `PREREQUISITE_UNKNOWN` | предпосылка не существует |
| `PREREQUISITE_SELF` | цель требует саму себя |
| `PREREQUISITE_CYCLE` | цикл в предпосылках |
| `PREREQUISITE_LATER_MODULE` | предпосылка из более позднего модуля |
| `MODULE_OBJECTIVE_UNKNOWN` | модуль ссылается на несуществующую цель |

Последнее — не формальность: зависимость от более позднего материала означает,
что программа требует исправления автором либо явного описания внешней
предпосылки отдельной целью. Молча «пропустить» её — это не персонализация.

## Ревизия курса

- Если каталог курса является корнем **собственного** Git-репозитория, ревизия
  — это полный OID коммита.
- Иначе — `local_snapshot` с `local-<sha256>` хешем дерева. Выдуманный коммит
  не подставляется.
- Курс, склонированный внутрь другого репозитория, **не** наследует его коммит:
  иначе ревизия описывала бы не тот проект.

## Область материалов

Материалы читаются из снимка `.botai/materials/<course_id>/<revision>/`,
собранного из `student_material_roots` с применёнными
`excluded_material_roots`. Исключения сильнее разрешений, сравнение идёт по
нормализованным путям, поэтому `lessons/../teacher/x.md` не обходит
исключение. Симлинки не копируются: ссылка на файл с секретами не должна
попадать в снимок.

Урок, изменённый в рабочей копии после принятия, текстом курса не становится.

## Ограничения

- Принятие не является аутентификацией преподавателя. Это происхождение
  (`acceptance_kind`), а не подпись.
- Снимок защищён хешем, но не от владельца ОС: тот, кто меняет файлы в
  `.botai/`, обнаружен будет, а остановлен — нет.
- Проверка JSON не обнаруживает смысловую утечку решения. Это отдельная
  сценарная оценка (см. `docs/botai-v2-design.md` §17.5).
- Managed-профиль хоста — PR-11; до него ограничения действуют как политика
  инструментов, а не как изоляция от свободного текста модели.
