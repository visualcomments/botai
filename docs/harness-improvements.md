# Дизайн улучшений harness для botai

## Статус

P0–P3 реализованы и проверены локально. P4 фиксирует следующий срез: принудительный лимит шагов учебной сессии.

## Цели

1. Не допускать бесконечного продолжения учебного цикла.
2. Предупреждать обучающегося до исчерпания лимита.
3. После лимита предлагать паузу или завершение, а не новый материал.
4. Делать состояние бюджета наблюдаемым через CLI.
5. Не превращать лимит активности в оценку успеваемости.

## Архитектура

`SESSION_STEP_BUDGET` и `SESSION_STEP_WARN_AT` находятся в `scripts/botai_core/tutoring.py`.
Счётчик `steps_taken` хранится в документе сессии и обновляется ядром при записи попытки. На уровне директивы `next_step` вызывается `step_budget_directive`:

```text
0..17   → обычный учебный цикл
18..23  → offer_break
24+     → close_or_pause
```

Приоритеты сохраняются:

```text
stop / missing consent
  > budget guard
  > course policy
  > prerequisites
  > ordinary teaching directive
```

Это означает, что запрос остановить занятие и обязательное согласие не блокируются самим бюджетом.

## CLI-поверхность

```bash
python3 scripts/cli.py session-budget --course <slug> [--learner <id>]
python3 scripts/cli.py session-budget --course <slug> --learner <id> --json
```

Команда только читает состояние. Она не меняет сессию, не запускает модель и не добавляет событий.

## Проверка

Обязательные сценарии:

- `17` шагов — состояние `ok`;
- `18` шагов — состояние `warn`, действие `offer_break`;
- `24` шага — состояние `exhausted`, действие `close_or_pause`;
- текст предупреждения объясняет паузу;
- текст исчерпания объясняет, что это ограничение внимания, а не наказание.

Запуск:

```bash
python3 scripts/evals/run.py session-step-budget
make check
```

## Ограничения

- Счётчик шагов — технический показатель длины сессии, не показатель мастерства.
- Лимит не меняет `graded`/`practice`/`unknown` и не меняет потолок помощи.
- Лимит не является заменой ручному решению обучающегося.
- Счётчик не читается из transcript; используется только записанное состояние сессии.
- Изменение значений лимита должно сопровождаться сценарием проверки и объяснением причины.

## Следующие кандидаты после P4

1. Добавить отдельный сценарий восстановления сессии после исчерпания бюджета.
2. Экспортировать бюджет в session handoff.
3. Перейти к изолированным worker-задачам для анализа курса и преподавательских отчётов.
4. Восстановить полноценную локальную директорию `tests/`, если она действительно должна поставляться в checkout.
