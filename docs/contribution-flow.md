# Первый вклад в открытый курс

Документ описывает, как ботай ведёт ученика к первому вкладу — и где именно
проходит граница между «агент помогает» и «агент делает за ученика».

## Главное правило

**Публикацию выполняет ученик.** Агент не делает `commit`, не делает `push`, не
открывает pull request, не публикует issue или комментарий. Он читает состояние
репозитория, объясняет, что в изменении, привязывает проверки к отпечатку
изменения и готовит **черновик текста**.

Это не обещание в промпте, а отсутствие пути в коде: в `botai_core/contribution.py`
нет функций `commit`, `push` или `open_pull_request`. Отсутствие — и есть
гарантия.

## Что ученик делает сам

```text
проверить выбранный репозиторий → создать свою ветку → изменить файл
→ прочитать diff → выбрать конкретные файлы → проверить staged diff
→ commit с собственной идентичностью → push в свой fork → открыть PR
```

Массовый copy-paste без объяснения не выдаётся: каждый шаг показывается с
последствием, которое ученик проверяет командой.

## Репетиция перед настоящим репозиторием

```bash
python scripts/cli.py contribute-rehearsal
python scripts/cli.py contribute-rehearsal --dest <путь> --dry-run
```

Команда создаёт одноразовый репозиторий в `.botai/git-practice/`, где нарочно
воспроизведено различие:

- `hello.txt` — изменён, но **не** в индексе (unstaged);
- `notes.txt` — в индексе (staged), но ещё не в коммите.

Работа в настоящем курсе не трогается. Первые шаги Git лучше делать там, где
ошибка ничего не стоит.

Это единственное место, где обвязка создаёт коммит, и он помечен как учебный:
личность в нём — вымышленная (`student@example.invalid`), и к заслугам ученика
он не относится. В настоящем репозитории коммит обязан нести идентичность
ученика — поэтому его и не делает агент.

## Состояния вклада

```text
DISCOVERY → TASK_SELECTED → GIT_PRACTICE → WORKING → LOCAL_CHECKED
→ DRAFT_READY → AWAITING_STUDENT_PUBLICATION → SUBMITTED → UNDER_REVIEW
→ REVISED → ACCEPTED|CLOSED
```

Альтернативный путь: `DRAFT_READY → PRIVATE_PACKAGE_READY → PRIVATELY_SUBMITTED`.
**Он не хуже публичного PR** и приводит к тем же достижениям. Если у ученика нет
аккаунта, форки запрещены или репозиторий защищён от внешних правок, это не
понижение — это другой равноправный путь.

`GIT_PRACTICE` можно пропустить после диагностической проверки навыка.

## Проверки привязаны к отпечатку изменения

Переход в `LOCAL_CHECKED` требует:

- **непустого** списка проверок — «мы проверили» без записи не принимается;
- отсутствия проваленных проверок;
- записи отпечатка изменения (`diff_hash`).

Отпечаток считается по нормализованному diff. Если ученик дополнил изменение,
сделал amend или force-push, отпечаток меняется, и **прежние проверки
обесцениваются**: они относились к другой ревизии. Переносить их на изменение,
которого никто не проверял, — это как раз то, от чего защищает запись.

Для роли `researcher` может не быть автотестов вовсе: тогда проверка помечается
`not_applicable` с пояснением. Это допустимо; пустой список — нет.

## Самоотчёт и наблюдение

`observation_source` принимает четыре значения: `local_git`, `remote_api`,
`human_teacher`, `learner_report`.

Сообщение «я отправил PR» сохраняется как `learner_report` и **не повышается**
до наблюдения. Переход в `ACCEPTED` требует наблюдения репозитория или
преподавателя: `record_acceptance` с `source="learner_report"` отклоняется с
кодом `ACCEPTANCE_REQUIRES_OBSERVATION`. Запись, которая принимает слова за
слияние, бесполезна для всех, кто будет её читать.

## Что видит ученик перед публикацией

```bash
python scripts/cli.py contribute-status --course <slug> --contribution <id>
python scripts/cli.py contribute-draft  --course <slug> --contribution <id> --out draft.md
```

`contribute-status` показывает состояние, отпечаток изменения, наблюдённую
рабочую копию и **блокирующие условия**:

- нет записанных проверок;
- статус прав `unknown`, `restricted` или `blocked`;
- проект требует раскрытия помощи ИИ, а текст не заполнен;
- изменение изменилось после проверки.

`contribute-draft` пишет черновик описания. Файл начинается с пометки
`<!-- ЧЕРНОВИК … -->`: описание, которое читается как готовый pull request,
ученик может вставить не прочитав, — а весь смысл в том, чтобы он прочитал.

Черновик включает: задачу и зачем изменение курсу, изменённые файлы, проверки с
наблюдениями, чек-лист публикации, раскрытие помощи ИИ и точные шаги, которые
ученик выполняет сам.

## Раскрытие помощи ИИ

`ai_disclosure.required` берётся из контракта курса. Если проект требует
раскрытия, пустой текст блокирует переход в `DRAFT_READY`.

Поле `confirmed_by_learner` по умолчанию `false` и устанавливается **только
человеческим каналом**. Подтверждение, пришедшее от модели, остаётся
`model_reported` и не даёт права на публикацию.

## Чтение Git тоже защищено

Даже read-only вызовы идут через ограниченный слой:

- **абсолютный путь** к доверенному `git`, а не имя, разрешаемое через `PATH`;
- **выключены** hooks, внешние diff-драйверы, `textconv`, системный конфиг, pager;
- `GIT_TERMINAL_PROMPT=0` — чтение никогда не ждёт ввода учётных данных;
- **вывод ограничен** и очищен от управляющих последовательностей: имя ветки
  может содержать escape-последовательность, а текст показывается человеку.

Изменяющие формы команд отклоняются:

| Разрешено | Отклонено |
|---|---|
| `git status`, `git diff`, `git log` | `git add`, `git commit`, `git push` |
| `git remote -v` | `git remote add` |
| `git branch` (список) | `git branch -D` |
| `git config --get` | `git config --add` |
| `git rev-parse HEAD` | `git reset`, `git merge`, `git rebase` |

Проверяются не только подкоманды, но и аргументы: `git remote -v` — наблюдение,
`git remote add` — настройка. Запрет всей подкоманды сделал бы обычное чтение
невозможным, поэтому различия разведены по аргументам.

## Различие форка и источника

`source_url` курса и `contribution_remote` ученика — **разные роли**, а не
взаимозаменяемые адреса. Совпадение проверяется по нормализованному адресу:

```text
https://user:token@github.com/o/r.git  →  github.com/o/r
git@github.com:o/r.git                 →  github.com/o/r
https://github.com/o/r                 →  github.com/o/r
```

Токен из адреса вырезается. Имя remote (`origin`, `upstream`) **ничего не
доказывает**: похожее имя — не тот же проект.

## Чего этот слой не делает

- Не проверяет, что ученик действительно написал текст сам: `assessed_by` и
  `independence_claim` — самоотчёты, а не сертификат.
- Не заменяет `CONTRIBUTING.md` проекта: он авторитетнее, и ученик читает его
  сам.
- Не публикует и не отзывает опубликованное. Отозвать уже отправленный PR
  программно нельзя.
- Не гарантирует, что проект примет вклад: форки, branch protection и правила
  рецензирования — внешние условия.
