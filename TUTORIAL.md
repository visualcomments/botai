## 1. Что это такое

**botai** (сокращение от *bot + AI*) — это «обвязка» (harness), которая
превращает обычного AI-кодинг-агента (Claude Code, Cursor, Codex, pi,
OpenCode и любые совместимые инструменты) в **сокурсника учебного курса**
— co-learner'а. Он не заменяет преподавателя и не делает домашние задания за
студента. Он **проходит курс вместе со студентом**:

- читает те же уроки, что и студент;
- разбирает задания на шаги (не решая их за студента);
- объясняет материал, когда в курсе его недостаточно;
- проверяет понимание;
- даёт обратную связь по выполненным попыткам;
- добавляет недостающий материал с указанием источника;
- ведёт досье прогресса по каждому студенту.

Репозиторий является **производной работой** проекта
[SECS](https://github.com/EvilFreelancer/secs) (Apache-2.0), переосмысленной
из тематики информационной безопасности в образовательную. Само решение
распространяется под лицензией **GNU GPL v3**.

Ключевая идея, зашитая в самую основу: **учиться вместе со студентом, а не
вместо него**. Это выражено в «золотых правилах» политики `AGENTS.md`, которые
агент не может обойти.

## 2. Какие проблемы решает

| Проблема | Как решает botai |
| --- | --- |
| «Не знаю, с чего начать задание» | Разбор задания на шаги с чек-поинтами, без готового ответа |
| «В курсе непонятно объяснено» | Объяснение по-своему + помеченный дополнительный материал с источником |
| «Я вроде понял, но не уверен» | Быстрые проверки понимания (квизы, пересказ, прогноз) |
| «Я сделал задание, проверьте» | Структурированная обратная связь: что правильно, что исправить, как исправить |
| «Я проходил курс неделю назад, всё забыл» | Досье прогресса, которое помнит уровень и предпочтения студента |
| «Преподаватель хочет отчёт по группе» | Прогресс-отчёт: что освоено, что в работе, что заблокировано |
| «Курс плохо покрывает тему» | Supplement-режим: найти пробел и заполнить его размеченным материалом |
| «Хочу пройти курс из каталога Open Education Club» | Старт курса из каталога через MCP: browse → README → fetch → co-learning |

Курсы берутся из каталога Open Education Club (лекции, лабораторные, задания
от вузов — например «Анализ данных в научной литературе», upstream которого
top-papers-graph, GPL-3.0-or-later) через MCP-сервер каталога. Агент показывает
студенту каталог, читает README и тянет материалы в `courses/`.

## 3. Структура репозитория

```
botai/
├── AGENTS.md                  # ПОЛИТИКА агента (самый важный файл)
├── CLAUDE.md                  # импорт AGENTS.md для Claude Code
├── README.md                  # обзор проекта
├── TUTORIAL.md                # этот документ
├── Makefile                   # интерфейс: setup, new-course, progress, lab
├── opencode.json              # настройки opencode (агент, скиллы, MCP)
├── LICENSE                    # GNU GPL v3
├── .agents/skills/            # 13 скиллов (реальные файлы)
│   ├── README.md
│   ├── <skill>/SKILL.md       # один каталог на скилл
│   ├── maintaining-course-progress/templates/progress-file.md
│   └── mapping-course-syllabus/templates/track.md
├── .claude/skills/            # симлинки → .agents/skills/ (для Claude Code)
├── .cursor/skills/            # симлинки → .agents/skills/ (для Cursor)
├── .opencode/                 # обвязка для opencode
│   ├── agent/                 # botai (primary) + tutor/mapper/reviewer/supplementer
│   ├── command/               # /session, /new-course, /progress, /review, /education-club, ...
│   ├── skills/                # симлинки → .agents/skills/ (для opencode)
│   └── README.md
├── courses/                   # ваши курсы (создаются `make setup`)
├── progress/                  # досье прогресса (создаются `make setup`)
├── docs/
│   ├── teaching-methods.md    # каталог методов преподавания
│   ├── course-agent-skills.md # экосистема образовательных скиллов
│   ├── open-source-contribution.md # режим опенсорс-соавтора курса
│   └── education-club.md      # подключение каталога Open Education Club (MCP)
└── dist/                      # временные файлы (git-игнорируются, кроме .gitignore)
```

Три ключевых элемента:

1. **Политика (`AGENTS.md`)** — что агент может и не может делать. Скиллы
   и сабагенты не могут ослабить эти правила.
2. **Скиллы (`.agents/skills/`)** — пошаговые инструкции для конкретных
   задач (объяснить, разобрать задание, оценить, дать фидбек, дополнить,
   стартовать курс из каталога).
3. **Интерфейс (`Makefile` + opencode)** — команды для управления курсами,
   прогрессом и каталогом Open Education Club.

## 4. Что нужно перед стартом

Программное обеспечение:

| Компонент | Зачем | Проверка |
| --- | --- | --- |
| Git | клонировать репозиторий, подтягивать курсы каталога | `git --version` |
| Python 3.9+ | MCP-сервер каталога Open Education Club | `python3 --version` |
| `make` | все команды жизненного цикла | `make --version` |
| OpenCode (рекомендуется) | полноценная работа с агентом, сабагентами, MCP | `opencode --version` |
| (опция) Claude Code / Cursor / Codex / pi | работа в другом агенте | их CLI |

**Как открыть терминал:**

- **Windows:** нажмите `Win + R`, введите `cmd` и нажмите Enter — откроется
  командная строка. Для команд `git` и `make` используйте **Git Bash**
  (ставится вместе с Git for Windows) или **WSL** — в обычном `cmd` команды
  `make` не работают, потому что Makefile использует команды Unix-шелла.
- **macOS:** нажмите `Cmd + Space`, введите «Terminal» и нажмите Enter.
- **Linux:** откройте любой эмулятор терминала (в Ubuntu — `Ctrl + Alt + T`).

**Как установить инструменты:**

| ОС | Git | Python 3 | make |
| --- | --- | --- | --- |
| Windows | [git-scm.com/download/win](https://git-scm.com/download/win) — вместе с ним появится Git Bash | [python.org](https://www.python.org/downloads/) — при установке отметьте «Add python.exe to PATH» | `choco install make` (Chocolatey, от администратора) или WSL: `sudo apt install make` |
| macOS | `xcode-select --install` (ставит git и make) | [python.org](https://www.python.org/downloads/) или `brew install python` | `xcode-select --install` |
| Debian/Ubuntu | `sudo apt install git` | `sudo apt install python3` | `sudo apt install make` |
| Fedora | `sudo dnf install git` | `sudo dnf install python3` | `sudo dnf install make` |
| Arch | `sudo pacman -S git` | `sudo pacman -S python` | `sudo pacman -S make` |

Проверка после установки: `git --version`, `python3 --version`,
`make --version` — каждая команда должна напечатать номер версии. Если
`python3` не найден на Windows, попробуйте `python --version` или
`py -3 --version`.

Аккаунты/доступ:

- API-ключ для LLM-провайдера (например Anthropic, OpenAI) — нужен агенту
  для генерации ответов. Настраивается в вашем агенте, не в этом репозитории.
- Для публикации на GitHub: `gh auth login` или PAT-токен (если хотите
  пушить изменения).

Для MCP-сервера каталога дополнительно (см. шаг 12):

```bash
git clone https://git.sourcecraft.dev/open-education-club-by-yandex/open-education-club-by-yandex.git
python3 -m pip install -r <checkout>/mcp/requirements.txt
export EDUCATION_CLUB_CATALOG=<checkout>   # путь к клонированному каталогу
```

## 5. Шаг 1. Установка и подготовка

### 5.1 Клонировать репозиторий и установить в отдельный проект

Установка всегда создаёт **отдельный, изолированный проект**. Файлы агента —
`AGENTS.md`, `agent.md` (`.opencode/agent/`), скиллы, слэш-команды и конфиг
`opencode.json` — устанавливаются **только внутри этого проекта** и никогда не
пишутся в глобальные конфиги opencode, Claude Code, Cursor или других
фреймворков.

> **Новичкам:** все команды ниже выполняются в терминале (на Windows — в Git
> Bash или WSL, см. раздел «Что нужно перед стартом»). Если команда не найдена
> (`make: command not found`, `git: command not found`) — вернитесь к разделу
> «Что нужно перед стартом» и установите недостающий инструмент.

```bash
git clone https://github.com/visualcomments/botai.git
cd botai
make install DEST=my-course-botai     # создать и заполнить ./my-course-botai/
cd my-course-botai
```

`make install` — это `python3 scripts/install.py --dest <dir>` (по умолчанию
`botai-project/`). Установщик:

- создаёт новый каталог проекта и копирует туда обвязку целиком (`AGENTS.md`,
  `CLAUDE.md`, `Makefile`, `opencode.json`, `.agents/`, `.opencode/`,
  `.claude/`, `.cursor/`, `docs/`);
- заново создаёт симлинк-фермы скиллов (`.claude/skills/`, `.cursor/skills/`,
  `.opencode/skills/` → `.agents/skills/`);
- создаёт рабочее пространство `courses/`, `progress/`, `dist/` и
  инициализирует git;
- **ничего не пишет** в глобальные каталоги (`~/.config/opencode`,
  `~/.claude`, `~/.cursor` и т.п.) и отказывается устанавливать в корень
  репозитория или в глобальный конфиг.

Предпросмотр без записи на диск: `python3 scripts/install.py --dest <dir>
--dry-run`.

### 5.2 (опция) Проверить окружение

```bash
make doctor
```

Вывод покажет ОС, наличие helper-инструментов (git, python3, node,
markdownlint) и текущее состояние каталогов `courses/`, `progress/`.

### 5.3 Проверить, что ничего не пропущено

```bash
ls -la
```

Вы должны увидеть `AGENTS.md`, `Makefile`, `opencode.json`, `LICENSE`,
`README.md`, каталоги `.agents/`, `.opencode/`, `docs/`.

> На этом этапе ещё **ничего не создаётся** в `courses/` и `progress/` — они
> появятся на шаге 4.

> Дальнейшие шаги туториала выполняются **из каталога установленного проекта**
> (`my-course-botai/`), а не из клона репозитория. Политика и скиллы действуют
> только в пределах этого проекта.

## 6. Шаг 2. Знакомство с политикой (AGENTS.md)

**`AGENTS.md` — это закон для агента.** Прочитайте его целиком. Ключевые
разделы:

1. **Golden rules** — восемь незыблемых правил. Самое главное: «Learn with,
   not instead of» (учиться вместе, а не вместо студента). Агент никогда не
   выполняет за студента задание и не выдаёт готовый ответ на оцениваемое
   задание.
2. **Operating modes** — три режима:
   - *Co-learning* (по умолчанию) — агент проходит курс вместе со студентом;
   - *Tutoring* — объясняет, разбирает, тренирует;
   - *Supplement* — находит пробелы курса и дополняет их.
3. **Student consent gate** — перед началом работы агент ОБЯЗАН спросить:
   текущий уровень студента, как подавать обратную связь (подсказки /
   подсказки затем полное решение / сразу полное решение), какие задания
   оцениваемые, а какие — тренировка. Ответы записываются в досье прогресса.
4. **Hard refusal list** — то, что агент отказывается делать при любых
   обстоятельствах (написать оцениваемое задание, дать ответы до попытки,
   выдумать источники, выдать себя за студента и т.д.).
5. **Graded-material rules** — ответы на оцениваемые задания являются
   градационным материалом. Агент не должен их читать, пока студент в этой
   сессии не сделает свою попытку.
6. **Skill catalog** — как маршрутизировать задачи по скиллам.

Если вы собираетесь работать в **Claude Code**, откройте `CLAUDE.md` — это
просто импорт `AGENTS.md`. В других агентах (pi, Cursor, Codex, OpenCode)
`AGENTS.md` читается напрямую.

## 7. Шаг 3. Разбор структуры и `make help`

### 7.1 Список всех команд

```bash
make help
```

Всё управление идёт через `make`. Команды:

**Рабочее пространство:**
- `make setup` — создать каталоги `courses/`, `progress/`, `dist/`;
- `make new-course NAME=<slug>` — создать новый курс из шаблона.

**Работа с курсом:**
- `make progress COURSE=<slug>` — сводка досье прогресса курса;
- `make review COURSE=<slug>` — запустить воркфлоу ревью работы студента;
- `make education-club` — проверить подключение каталога Open Education Club
  (`EDUCATION_CLUB_CATALOG=<путь>`).

**Гигиена:**
- `make doctor` — диагностика окружения: ОС, инструменты, курсы, прогресс;
- `make lint` — проверка markdown (нужен markdownlint-cli2);
- `make clean` — удалить временные файлы (с `DRY=1` —
  только предпросмотр, без удаления).

### 7.2 Что такое скиллы

Скиллы лежат в `.agents/skills/`, каждый — в своём каталоге с файлом
`SKILL.md`. Одиннадцать скиллов:

| Скилл | Назначение |
| --- | --- |
| `mapping-course-syllabus` | превратить документы курса в трассу модулей и целей |
| `maintaining-course-progress` | вести досье прогресса (уровни, предпочтения, заметки) |
| `planning-study-sessions` | спланировать сессию или учебный план |
| `breaking-down-assignments` | разбить задание на шаги, не решая его |
| `explaining-concepts` | объяснить материал на уровне студента, Socratic-first |
| `assessing-understanding` | быстрые проверки понимания до и после обучения |
| `giving-feedback` | ревью попытки: что верно, что исправить, как |
| `providing-supplementary-material` | найти пробел курса и заполнить его с источником |
| `creating-practice-exercises` | сгенерировать дополнительные упражнения |
| `vetting-educational-material` | проверить сторонние материалы и скиллы перед использованием |
| `reporting-learning-progress` | отчёты о прогрессе для студента или преподавателя |

## 8. Шаг 4. Создание рабочего пространства

Создайте каталоги под ваши курсы и досье прогресса:

```bash
make setup
```

Ожидаемый результат:

```
workspace ready:
  .../courses   (course materials go here)
  .../progress  (progress records go here)
  .../dist      (temporary files, git-ignored)
next: make new-course NAME=<slug>
```

После этого в репозитории появятся каталоги `courses/`, `progress/`, `dist/`.
Они добавлены в `.gitignore` — это значит, что ваши рабочие материалы не
попадут в коммиты.

## 9. Шаг 5. Создание курса

### 9.1 Создать каркас курса

```bash
make new-course NAME=my-course
```

Или с человекочитаемым названием:

```bash
make new-course NAME=python-101
```

Результат — каталог `courses/python-101/` с:

```
courses/python-101/
├── README.md      # каркас с пометкой "fill in the syllabus"
├── syllabus.md    # заготовка: один пустой модуль
├── lessons/       # пустой каталог для уроков
├── assignments/   # пустой каталог для заданий
└── references/    # пустой каталог для материалов
```

### 9.2 Заполнить программу курса

Откройте `courses/python-101/syllabus.md` и опишите модули: тема, цель
обучения, предварительные требования.

```
# Syllabus

## Modules

1. Variables and types - уметь объявлять переменные и работать с типами
2. Loops - уметь писать циклы for/while
```

Положите материалы уроков в `lessons/`, а листы заданий — в `assignments/`.

### 9.3 Пусть агент построит трассу курса

Запустите агента и попросите:

```
Собери трассу курса python-101: прочитай syllabus.md и материалы, 
построй карту модулей, целей и предварительных требований.
```

Агент использует скилл `mapping-course-syllabus` и создаст
`courses/python-101/track.md`. Важно: агент ничего не выдумывает — каждая
цель и требование должны прослеживаться до документа курса.

## 10. Шаг 6. Первая учебная сессия

### 10.1 Запустить агента из каталога установленного проекта

**Пошагово (opencode):**

1. Откройте терминал (на Windows — Git Bash или WSL) и перейдите в каталог
   установленного проекта:

   ```bash
   cd my-course-botai
   ```

2. Запустите opencode:

   ```bash
   opencode
   ```

   Откроется интерактивный интерфейс (TUI). Внизу — строка ввода, в ней —
   имя активного агента. По умолчанию это `botai` (задано в `opencode.json`).
   Примерно так:

   ```
   ┌────────────────────────────────────────────────────────────┐
   │  botai · <ваша модель>                                     │
   │                                                            │
   │  > _                                                       │
   └────────────────────────────────────────────────────────────┘
   ```

3. **Проверьте, что агент `botai` включён и готов к работе:**
   - введите `/agents` и нажмите Enter — в списке агентов должен быть `botai`
     (primary);
   - или задайте контрольный вопрос: «Кто ты и как ты работаешь?» — бот
     должен представиться сокурсником, назвать режимы работы (co-learning,
     tutoring, supplement, open-source contributor) и сослаться на политику
     `AGENTS.md`;
   - если активен другой агент — переключитесь на `botai` через `/agents`.

4. Начните сессию: «Изучай курс python-101 вместе со мной». Агент пройдёт
   consent-gate (см. 10.2) и начнёт co-learning.

или в другом агенте — просто откройте терминал в каталоге **установленного
проекта** (например `my-course-botai/`) и запустите свой агент. Политика
`AGENTS.md` и скиллы подхватятся автоматически — и только в этом проекте.

### 10.2 Пройти consent gate

В начале сессии агент задаст вопросы (это обязательно):

1. **Текущий уровень** по предварительным требованиям курса. Например:
   «Я знаю переменные, но циклы не проходил». Студент может выбрать:
   тестирование или самооценка.
2. **Формат обратной связи**: подсказки / подсказки, затем полное решение /
   сразу полное решение.
3. **Какие задания оцениваемые**, а какие — тренировка.

Ответы агент сохранит в `progress/<course>.md` через скилл
`maintaining-course-progress`.

> Если курс — опенсорс-проект и его лицензия разрешает вклад, агент во время
> знакомства также расскажет о возможности стать **контрибьютором курса**:
> как организована такая работа (реальные коммиты делает студент, агент
> планирует, обучает и готовит черновики) и спросит, интересна ли вам эта
> роль. Подробнее — в шаге 13.

### 10.3 Провести сессию

Пример запроса студента:

```
Пройдём первый модуль курса python-101: переменные. Я только начал.
```

Агент перейдёт в режим co-learning, объяснит тему по одному шагу за раз,
проверит понимание и оставит место для практики.

## 11. Шаг 7. Разбор задания, объяснение, проверка

### 11.1 Разбор задания без решения

Студент: «Я не знаю, с чего начать задание 2».

Агент использует `breaking-down-assignments` и выдаёт карту шагов:

```
Assignment: task-2   [graded]

1. Прочитать входные данные        (нужно: файлы, JSON)   checkpoint: что лежит в файле?
2. Разобрать структуру             (нужно: типы данных)   checkpoint: какой тип у каждого поля?
3. <...>
Last step: твоя очередь. Покажи попытку на шаге 3 — я проверю.
```

Ключевое: для оцениваемого задания агент **не** доходит до готового ответа —
последний шаг остаётся за студентом.

### 11.2 Объяснение материала

Студент: «Что такое список в Python?»

Агент (`explaining-concepts`):
1. сначала задаёт 1–2 вопроса, чтобы понять уровень;
2. объясняет одну идею за раз с примером;
3. использует вопросы (Socratic method) перед ответами;
4. привязывается к терминам курса.

### 11.3 Проверка понимания

Студент: «Я понял!»

Агент не верит на слово — он проводит быструю проверку
(`assessing-understanding`): попросит пересказать своими словами, предсказать
результат, применить на новом примере или найти ошибку. Только после этого
двигается дальше.

---

## 12. Шаг 8. Обратная связь и ревью

### 12.1 Отправить работу на ревью

Студент: «Я сделал задание 1, вот мой код/текст».

Агент (`giving-feedback`) отвечает по шаблону:

```
Что правильно:
  <конкретные верные части>

Что нужно исправить:
  <пробел 1> → как найти и исправить самому: <стратегия>
  <пробел 2> → ...

Для оцениваемого задания: исправление — твоё. Попробуй стратегию и пришли результат.
```

Правила:
- сначала — что правильно (чтобы студент не переписывал верное);
- конкретный пробел, а не «логика неверная»;
- для оцениваемого задания — только стратегия исправления, никогда готовое
  решение;
- для тренировочного (если студент выбрал «полное решение») — полное решение
  для сравнения.

### 12.2 Ревью через команду

```bash
make review COURSE=python-101
```

Команда подскажет воркфлоу ревью и напомнит: не раскрывать ответ до попытки.

## 13. Шаг 9. Дополнение курса (supplement)

Студент: «В курсе не объясняется, что такое рекурсия, а в задании она нужна».

1. Агент сначала подтверждает пробел по тексту курса (не выдумывает его).
2. В режиме supplement готовит материал: объяснение, пример, упражнения или
   внешнюю ссылку.
3. **Каждый supplement помечен**: «это выходит за пределы курса», с
   источником. Агент не выдаёт свой материал за текст курса.
4. Агент не выдумывает источники. Если реального источника нет — говорит об
   этом.

Можно вызвать и напрямую: «Найди пробелы в модуле 2 и дополни их».

## 14. Шаг 10. Прогресс и отчёты

### 14.1 Посмотреть досье прогресса

```bash
make progress COURSE=python-101
```

Если досье ещё нет — команда скажет об этом и подскажет, что его ведёт агент.

### 14.2 Попросить агента составить отчёт

Студент или преподаватель: «Составь отчёт по моему прогрессу в python-101».

Агент (`reporting-learning-progress`) выдаст:

```
# Progress: python-101 for <student>

Overview: <где студент сейчас, простым языком>
Track: <модуль> - <статус>
Mastery: <цель> - <уровень>
Что заблокировано: <цель> - <причина> - <рекомендация>
Следующие шаги:
1. <действие>   (почему)
Открытые вопросы: <из досье>
```

Отчёт говорит о **мастерстве**, а не об активности («прошёл модуль 2» ≠
«может развернуть список без подсказок»). Агент не сообщает градационные
ответы и работы студентов.

## 15. Шаг 11. Старт курса из каталога Open Education Club

Курсы для co-learning берутся из каталога Open Education Club (лекции,
лабораторные, задания от ведущих вузов — включая «Анализ данных в научной
литературе», upstream которого top-papers-graph, GPL-3.0-or-later) через
MCP-сервер каталога. Это заменяет предустановленный практический трек: агент
сам находит курс, читает его README и тянет материалы в рабочее пространство.

### 15.1 Что делает агент

1. Показывает студенту каталог (`education-club_list_courses`).
2. Читает README кандидатов (`education-club_get_course`): аудитория,
   пререквизиты, формат, часы.
3. Проходит consent-gate (уровень, формат обратной связи, оцениваемые vs
   тренировочные задания).
4. Тянет материалы курса в `courses/<slug>/`
   (`education-club_fetch_course`) и начинает co-learning.

### 15.2 Подключение каталога (для оператора)

```bash
git clone https://git.sourcecraft.dev/open-education-club-by-yandex/open-education-club-by-yandex.git
python3 -m pip install -r <checkout>/mcp/requirements.txt
EDUCATION_CLUB_CATALOG=<checkout> make education-club   # проверить подключение
```

Затем в opencode: `/education-club`, чтобы выбрать курс и начать занятие.

> Оцениваемые задания курса — градационный материал. Ответы открываются агентом
> только после попытки студента и его явной просьбы проверить. MCP-сервер
> каталога не отдаёт ответы — только публичные материалы курса.

### 15.3 Работа с курсом как со студентом

Студент работает с загруженным курсом как с обычным: читает уроки через
агента, делает задания, отправляет на ревью. Прогресс ведётся в `progress/`.

## 16. Шаг 12. MCP-сервер и команды opencode

### 16.1 MCP-сервер каталога Open Education Club

Каталог подключается MCP-сервером из клона репозитория
`open-education-club-by-yandex` (файл `mcp/catalog-mcp.py`). Инструменты:

- `education-club_list_courses()` — весь каталог;
- `education-club_get_course(slug)` — метаданные + README курса;
- `education-club_fetch_course(slug, dest)` — клонирование материалов курса в
  рабочее пространство.

Проверка сервера:

```bash
python3 <checkout>/mcp/catalog-mcp.py --list
# → tools:
#   list_courses()
#   get_course()
#   fetch_course()
```

Сервер зарегистрирован в `opencode.json` под именем `mcp.education-club` через
`{env:EDUCATION_CLUB_CATALOG}`. После установки зависимостей и установки
переменной перезапустите opencode.

### 16.2 Команды (slash-команды) opencode

В `.opencode/command/` есть готовые команды:

| Команда | Что делает |
| --- | --- |
| `/setup` | создать рабочее пространство и проверить окружение |
| `/session <тема>` | начать co-learning сессию (проходит consent gate) |
| `/new-course <имя>` | создать курс и собрать трассу |
| `/progress <курс>` | сводка прогресса |
| `/review <работа>` | ревью попытки студента |
| `/supplement <тема>` | найти и заполнить пробелы курса |
| `/contribute <проект>` | режим опенсорс-соавтора: способы участия, онбординг, первый вклад, связь с разработчиками |
| `/education-club [курс]` | старт курса из каталога Open Education Club через MCP: просмотр каталога, чтение README, загрузка курса, начало co-learning |

### 16.3 Сабагенты opencode

В `.opencode/agent/`:

- `botai.md` — primary-агент (co-learner, агент по умолчанию);
- `tutor.md` — объясняет, разбирает, проверяет (edit: deny);
- `mapper.md` — строит трассу курса, ведёт прогресс;
- `reviewer.md` — ревью попыток (edit: deny);
- `supplementer.md` — дополнительные материалы;
- `contributor.md` — онбординг в опенсорс-курс как со-разработчика (edit: deny).

`tutor`, `reviewer` и `contributor` имеют `edit: deny`, чтобы «не решать за
студента» — они возвращают результаты и черновики, primary-агент записывает
их в досье, а в опенсорс-режиме коммит и публикацию делает сам студент.

## 17. Шаг 13. Режим опенсорс-соавтора курса

Некоторые курсы — это ещё и опенсорс-проекты: репозиторий и есть курс, а
слушатели не сдают одноразовые ДЗ, а **становятся участниками проекта**.
Каждый вклад — код, тест, документация, урок, проверка фактов или помощь
другому участнику — остаётся в проекте и переиспользуется следующими
потоками. Пример — [top-papers/top-papers-graph](https://github.com/top-papers/top-papers-graph),
upstream курса «Анализ данных в научной литературе» из каталога
Open Education Club. Подобные сообщества работают и на платформах вроде
[SourceCraft](https://sourcecraft.dev) (Яндекс) — с рейтингами, грантами и
достижениями для контрибьюторов.

Чтобы агент стал вашим партнёром по со-разработке, скажите ему, например:
«хочу стать одним из разработчиков курса scireason-course» или выполните
команду `/contribute <проект>`.

### 17.1 Что делает агент в этом режиме

1. **Рассказывает обо всех способах участия.** Никакого «только код»: код и
   инфраструктура, учебные материалы, документация, научная экспертиза и
   проверка данных, а также помощь сообществу (triage issues, ревью PR, помощь
   новичку). Для каждого варианта — что остаётся в проекте после вклада.
2. **Помогает слушателю любого уровня освоиться со средой.** От «первый раз
   в терминале» до опытного разработчика: аккаунт, fork → clone → branch →
   commit → push → pull request, по одному шагу за раз; запуск быстрого старта
   проекта в офлайн-режиме (без платных API).
3. **Планирует первый вклад.** «Good first issue», правка документации,
   воспроизведённый пример или маленький тест; если подходящей задачи нет —
   помогает сформулировать новую issue.
4. **Налаживает связь с другими разработчиками курса.** Находит каналы
   сообщества (issues, обсуждения, чат/Telegram/Discord, мейнтейнеры), помогает
   написать первое сообщение — которое вы проверяете и отправляете сами, —
   и учит async-этикету по code of conduct проекта.

### 17.2 Кто делает вклад

Настоящие коммиты и публикации делает **вы**. Агент планирует, обучает и
готовит черновики (первое сообщение, issue, описание pull request), но вы их
проверяете, дописываете и отправляете от своего имени. Агент никогда не
коммитит и не публикует за вас и не выдумывает вклад.

### 17.3 Ограничения

- Правила градационного материала из `AGENTS.md` остаются в силе: ответы на
  оцениваемые задания — не раньше попытки студента. Режим нацелен на настоящий
  апстрим-проект, а не на ответы.
- Соблюдайте лицензию проекта: вклад передаётся под лицензией проекта,
  сторонние материалы — только со совместимой лицензией и атрибуцией.
- Раскрывайте использование ИИ там, где проект этого требует.
- Не добавляйте секреты, закрытые PDF, персональные данные и файлы без понятной
  лицензии.

Полный справочник режима — [docs/open-source-contribution.md](docs/open-source-contribution.md),
процедура — скилл `onboarding-open-source-contributors`.

## 18. Частые сценарии вопрос-ответ

**Q: Нужно ли агент для чтения материалов?**
A: Нет. Вы можете читать файлы курсов в `courses/` как обычные файлы. Агент
помогает с объяснением, разбором и обратной связью.

**Q: Агент сделает задание за меня?**
A: Нет. Политика (`AGENTS.md`) запрещает это. Для оцениваемых заданий агент
даёт разбор на шаги и стратегию, но финальное решение — за вами.

**Q: Что если я не хочу указывать свой уровень?**
A: Агент продолжит в режиме tutoring с настройкой `prefer-ask` (по умолчанию
только подсказки) и будет проверять понимание перед новым материалом.

**Q: Можно ли использовать без opencode?**
A: Да. Политика и скиллы читаются напрямую pi, Cursor, Codex, Claude Code
(через `CLAUDE.md`). opencode просто даёт удобные команды, сабагенты и MCP.

**Q: Где взять готовый курс, чтобы пройти вместе с агентом?**
A: Курсы берутся из каталога Open Education Club через MCP: `/education-club`
покажет каталог, прочитает README и загрузит выбранный курс в `courses/`.
Свои курсы создавайте в `courses/` через `make new-course`. Если вы хотите
стать со-разработчиком самого опенсорс-курса — используйте режим
опенсорс-соавтора (`/contribute <проект>`): агент расскажет о ролях, поможет
освоиться и наладит связь с командой проекта.

**Q: Агент сделает вклад в опенсорс-курс за меня?**
A: Нет. В режиме опенсорс-соавтора агент планирует, обучает и готовит
черновики (первое сообщение, issue, описание PR), но коммит и публикацию вы
делаете сами — иначе вклад был бы не вашим.

**Q: Почему `courses/` и `progress/` не видны в git?**
A: Они в `.gitignore`. Это рабочие данные, которые не должны попадать в
публичный репозиторий.

## 19. Типичные ошибки и как их избежать

| Ошибка | Что происходит | Как избежать |
| --- | --- | --- |
| Копирование скиллов/агентов в глобальный конфиг (`~/.config/opencode`, `~/.claude`) | Политика и агенты начинают действовать во всех проектах | Устанавливайте через `make install DEST=<dir>` — файлы агента остаются в рамках отдельного проекта |
| Запуск агента не из корня репозитория | Политика и скиллы не подхватываются | Всегда запускайте агента из каталога установленного проекта |
| Забыли `make setup` | Нет `courses/`, `progress/` | Выполните `make setup` перед первым курсом |
| Изменение `AGENTS.md` без перезапуска opencode | Агент работает по старой политике | Перезапустите opencode после правок конфига |
| Запрос готового ответа на оцениваемое задание | Агент откажется (hard refusal) | Просите разбор на шаги и стратегию |
| Правка скилла в `.claude/skills/` или `.opencode/skills/` | Симлинк ведёт в `.agents/skills/` — правка «пропадёт» | Всегда правьте файлы в `.agents/skills/<name>/SKILL.md` |
| Просьба агенту «закоммить за меня» в опенсорс-режиме | Агент откажется (вклад должен быть вашим) | Агент готовит черновик, вы коммитите и публикуете сами |
| MCP каталога не виден в opencode | Не установлены зависимости, не задан `EDUCATION_CLUB_CATALOG` или не перезапущен opencode | `pip install -r <checkout>/mcp/requirements.txt`, `export EDUCATION_CLUB_CATALOG=<checkout>`, затем перезапуск |
| `make new-course` без `NAME=` | Команда завершится с ошибкой использования | `make new-course NAME=<slug>` |
| Забыли, какие задания оцениваемые | Агент не знает границ «нет готовых ответов» | Пройдите consent gate и фиксируйте split в досье |

## Приложение: полный контрольный список первого запуска

- [ ] `git clone https://github.com/visualcomments/botai.git && cd botai`
- [ ] `make install DEST=my-course-botai` — создан отдельный проект
- [ ] `cd my-course-botai && make doctor` — окружение проверено
- [ ] Прочитали `AGENTS.md` (политика)
- [ ] `make help` — список команд изучен
- [ ] `make setup` — рабочее пространство создано
- [ ] `make new-course NAME=python-101` — курс создан
- [ ] `courses/python-101/syllabus.md` заполнен, материалы в `lessons/`
- [ ] Агент собрал трассу курса (`track.md`)
- [ ] opencode запущен, агент `botai` активен (проверка `/agents` или контрольный вопрос)
- [ ] Первая сессия: consent gate пройден
- [ ] Задание разобрано на шаги, попытка отправлена на ревью
- [ ] `make progress COURSE=python-101` — досье ведётся
- [ ] (опц.) MCP каталога включён: клонирован open-education-club-by-yandex,
      `EDUCATION_CLUB_CATALOG` задан, зависимости установлены
- [ ] (опц.) `/education-club` — курс из каталога выбран и загружен в `courses/`
