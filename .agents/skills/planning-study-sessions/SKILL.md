# Planning Study Sessions

A good session has one idea per step and a stopping point. This skill plans the
agenda from the course track (`mapping-course-syllabus`) and the student's
recorded level (`maintaining-course-progress`), and keeps the plan honest about
what is not yet verified.

## When to Use

- Before a session: set what will be taught, practised, and checked
- A student asks for a study plan for the next two weeks
- Resuming after a gap: rebuild the agenda from the record
- A student is stuck: plan a prerequisite review instead of repeating the same
  lesson louder

## When NOT to Use

- **Choosing what the student needs to learn next** — the track and the
  progress record decide that; this skill only schedules it
- **Verifying understanding** — that is `assessing-understanding`
- **Single-session improvisation** — if the student just asks a question,
  answer it; planning is for multi-step work

## Planning rules

1. **Level first.** Read the progress record before planning anything. A plan
   that ignores the recorded level repeats the previous session's mistakes.
2. **Prerequisites verified before new material.** If the next objective's
   prerequisites are `unverified` or `blocked`, the plan leads with a check
   (`assessing-understanding`), not new content.
3. **One idea per step.** Each agenda item teaches or practises exactly one
   objective. Confirming each step before the next is what makes pacing
   possible.
4. **Graded vs practice is respected.** Graded tasks appear as review-and-fix
   items, never as "do it for the student".
5. **Capacity first.** Plan a stopping point and a break. Overload is a
   stop condition, not a schedule problem.
6. **A plan is a hypothesis.** It states what will be checked at the end so the
   next plan can be corrected from evidence (`assessing-understanding`).

## Single session

```
Before:  confirm consent gate + level for this session (progress record)
1. Check  — 2 quick questions on the prerequisite (2 min)
2. Teach  — one objective, one example, check-in (20 min)
3. Practise — one problem the student solves, hints only (15 min)
4. Review — what was demonstrated, record it (maintaining-course-progress)
```

## Multi-week plan

- Map modules and objectives from the track; order by stated prerequisites.
- Interleave practice and review of earlier objectives (spacing) rather than
  front-loading new content.
- Leave buffer for a `blocked` objective to become a prerequisite review.
- Produce the plan as a dated checklist the student can follow, and re-plan
  after each session from the recorded outcome.
