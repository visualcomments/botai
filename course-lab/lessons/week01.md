# Week 01 — Вход в open-source проект

## Результат недели

Участник запускает воспроизводимое офлайн-демо, понимает цепочку артефактов и проходит первый цикл issue -> изменение -> проверка -> pull request.

## Зачем это проекту

Онбординг является частью продукта. Если новый человек не может повторить запуск, курс и инструмент не масштабируются.

## Практика

```bash
./scripts/bootstrap.sh  # Windows: .\scripts\bootstrap.ps1
top-papers-graph demo-run --llm-provider mock
top-papers-graph smoke-all
```

Откройте `runs/demo_*/temporal_kg.json` и `hypotheses.json`. Найдите один непонятный шаг, слабое сообщение или недостающий пример.

## Вклад по ролям

- **Исследователь:** описывает, что делает гипотезу проверяемой.
- **Эксперт:** отмечает утверждение, которому не хватает evidence.
- **Разработчик:** добавляет smoke-test или улучшает ошибку запуска.
- **Координатор:** исправляет quickstart или создаёт first-contribution issue.

## Готово, когда

Есть небольшой PR или экспертный артефакт, способ проверки и краткое объяснение пользы для следующего участника.
